# Find Job 职位库助手

该 Chrome MV3 扩展是职位库与用户已登录 BOSS 直聘页面之间的本地通道。日常使用时，扩展返回城市、职位列表与职位详情；只有用户逐条审核文案并最终确认后，才会在后台聊天页执行真实发送。

## 首次安装

1. 在 Chrome 地址栏打开 `chrome://extensions`。
2. 打开右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本目录：`browser-extension/job-library`。
5. 在同一 Chrome 中打开并登录 `https://www.zhipin.com/`。
6. 回到平台左侧一级菜单“职位库”，点击右上角连接状态重新检查。

扩展更新后，在扩展管理页点击本扩展的“重新加载”即可。

## 权限与边界

- `tabs`：复用或创建一个非激活的 BOSS 页面。
- `scripting`：在 BOSS 页面主执行环境发起同源请求，并在真实发送时操作聊天输入框与发送按钮。
- 站点权限仅覆盖本地开发地址、`xingxingtech.cn` 和 `www.zhipin.com`。
- 扩展不读取或导出 Cookie、密码、手机号、聊天记录和简历。
- 扩展不接收整批任务；每次只预检或发送一个岗位，批量顺序由页面严格串行调度。
- 只在用户点击搜索、加载更多或岗位卡片时请求数据；请求串行执行并保留最小间隔。
- 用户切换城市后，扩展只在本次主动搜索时将专用 BOSS 搜索页同步到所选城市；不会改动正在浏览的岗位详情页，也不会后台轮询城市状态。
- 列表返回后会逐条核对岗位城市。与所选城市不一致或没有城市信息的岗位不会展示；整批结果都不一致时立即停止并提示重新检查。
- 扩展不做后台轮询，也不主动探测账号状态。只有本次用户操作返回可恢复的页面会话异常时，才正常刷新 BOSS 页面一次并重试原请求一次。
- 每次用户操作最多自动刷新一次；真实限流、登录失效、安全验证以及刷新后仍异常时均立即停止，不循环刷新、不绕过验证。

## 调用协议

网页 Content Script 只接受六个动作：

- `ping`：检查扩展是否可用。
- `list_cities`：通过 `/wapi/zpgeek/common/data/city/site.json` 读取当前 BOSS 城市目录，返回可用于真实搜索的九位城市代码。
- `search_jobs`：按岗位名称、页码和选中城市搜索职位；城市代码必须为九位数字。
- `get_job_detail`：使用列表响应中的 `securityId` 获取最新详情。
- `preflight_greeting`：只读检查登录、安全验证、岗位有效性和聊天标识，不建立沟通关系。
- `send_greeting`：单次建立一个岗位的沟通关系，在专用后台聊天页填入一条最终文案并点击发送。

真实发送不会自动重试 `friend/add` 或页面“发送”点击。BOSS 已配置默认招呼语时，扩展允许平台先发送默认招呼语，再进入聊天页发送本次定制文案。验证码、限流、登录失效和回执未知仍会立即停止。

网页与扩展通过当前页面的 `window.postMessage` 和 `chrome.runtime.sendMessage` 通信。Service Worker 会校验调用来源，只接受项目本地地址和正式域名。

## 会话恢复

扩展优先复用当前激活或最近访问、且已经加载完成的 BOSS 标签页。搜索岗位、读取详情或发送前预检返回 `code=37` 时，扩展会立即对该 BOSS 标签页执行一次普通刷新，等待页面稳定后只重试刚才的只读请求一次。该机制按用户操作即时触发，不依赖后台定时器，也没有跨操作冷却；`friend/add` 和发送点击本身仍不会自动重试。

如果一次自动刷新后会话仍未恢复，发送进度页会显示“刷新 BOSS 状态，重试这一条并继续”。该按钮只用于尚未提交消息的安全失败；发送结果未知时不会出现，避免重复消息。

以下状态不会触发自动刷新：

- HTTP 或接口 `429` 访问频率限制；
- 登录页、安全验证页或验证码；
- 普通网络错误、未知接口错误；
- 自动刷新后仍返回异常。

该机制不导出、保存或替换 Cookie/token，也不会定时刷新页面。真实发送所需的临时页面 Token 只在注入的 BOSS 页面执行环境中使用，不会返回 WebUI 或写入扩展存储。

城市同步同样只使用浏览器正常页面导航：若已有 BOSS 搜索页但城市不同，则单次切换该搜索页；若只有岗位详情等其他页面，则新建一个非激活搜索页，避免打断用户浏览。

## 维护

BOSS 职位与沟通链路来自其网页当前使用的内部接口和 DOM，并非公开开放 API，字段、路径和选择器可能变化。接口漂移时优先更新 `boss-data.js`、`boss-greeting.js` 与 `service-worker.js`，不把平台原始响应直接暴露给业务页面。

验证命令：

```powershell
cd browser-extension/job-library
npm test
node --check service-worker.js
node --check content-script.js
```
