# PC 与手机界面适配

更新：2026-11-06。本轮覆盖整个 Web 平台，先验证 PC 核心流程，再完成手机布局与交互改造。依据见 [专项设计](designs/2026-11-06-pc-mobile-ui-adaptation.md)，最终结果见 [实施记录](designs/2026-11-06-pc-mobile-ui-implementation.md)。

## 目标与技术取舍

- 沿用 Vue、Element Plus、原 API 和蓝白／浅绿主题，不引入 UI 库，不做平板专项。
- PC 保留多栏，手机使用单列主任务、列表／详情切换和资料 Sheet。浏览器能力与窗口宽度分开判断。
- 普通页面由主内容区滚动；聊天由消息区滚动；弹层由主体滚动，重要操作保留可见。
- 手机触控区域至少 44px，主按钮 48px，输入正文 16px；代码与宽表格允许局部横向滚动。
- 不改变模型、数据库、文档解析、公众号任务与服务端权限契约。

## 调用链与依赖

`main.js → theme.css + mobile.css → App.vue 路由／导航 → 页面组件 → 原 API 或扩展 bridge`。

`platform-capabilities.js` 识别移动浏览器；`composer-keyboard.js` 判断 Enter 是否发送；`use-dialog-focus.js` 只管理弹层焦点、关闭返回和 VisualViewport 高度，不处理业务请求。匹配证据抽成 `CareerMatchEvidence.vue`，PC 侧栏与手机条目复用同一份报告数据。

公共规则集中在 `mobile.css`；匹配报告、上下文表单、紧凑 PC 笔试等规则保留在对应组件。布局变化不创建第二套业务状态。

## 视口与路由边界

聊天与弹层使用 VisualViewport 的 resize 事件更新高度，关闭或卸载清理监听和 CSS 变量，不增加轮询。上下文、岗位、招呼、模型连接、面经导入和收集 Sheet 使用动态高度、安全区与可滚动主体。匹配报告继续使用原生 dialog。

评测新增 `/evaluations/datasets`、`/evaluations/experiments`、`/evaluations/metrics`，总览保留 `/evaluations`；未知子路由回退总览，继承原管理员权限。现有 Nginx 的 `try_files $uri $uri/ /index.html` 支持前端子路由刷新，本轮没有修改部署配置。

手机可读服务器已有会话资料和报告，但本轮没有新增远程电脑扩展控制、手机系统音频共享或 App 执行器。窄 PC 仍按原逻辑检测真实扩展能力。

## 本地验证

- 前端 Node 测试 295 项通过，Vite 构建通过；已有大 chunk 提示仍存在。
- 首批 PC 基线 11 项通过后才进入手机样式改造；最终全量 Playwright 47/47 通过（Chromium 45、Firefox 基础 2），证据见实施记录。
- PC 核心路由：900×420、1024×600、1093×614、1280×720、1440×900、1920×1080。
- 手机聊天：360／375／390／430px、844×390 横屏、390×430 键盘近似高度；各模块另有交互断言。
- API、模型和扩展测试使用本地 fixture，不调用付费模型或真实发送招呼语。移动 UA 的 Chromium 测试不是 Safari 真机验收。

```powershell
npm --prefix web-ui test
npm --prefix web-ui run build
npm --prefix web-ui run test:e2e:responsive
# 全量包含既有检索、招呼和匹配业务回归
cd web-ui
npx playwright test --reporter=line
```

## 2026-11-06 压力审查修复

原 47 项成功路径不能代表全部状态已可靠。本次补充 [压力回归](../web-ui/e2e/grill-regression.spec.js)，覆盖 12 个已确认问题及旧评估迟到响应，修复前证据继续保留在 [审查报告](designs/2026-11-06-dual-ui-grill-review.md)。实现和最终验证见 [修复记录](designs/2026-11-06-dual-ui-grill-fixes.md)。

- 短屏标题与快捷入口分行，保留四项能力和发送操作；长 URL 正文允许断行，代码与表格局部滚动，聊天和技能阅读消费 16px 正文变量。
- 新会话读取成功后再切换状态，重复选择当前会话保留草稿；技能按 ID 保留会话内草稿，只接受最新详情响应，保存后显示成功反馈。
- `use-history-layer.js` 在移动浏览器为导航、详情、辅助抽屉和弹层建立同 URL 返回层；系统返回先关闭一层，显式关闭消费历史层，主导航等待层清理后再进入路由，忙碌表单保留等待状态。PC 窄窗口仍按桌面能力运行。
- 简历工作区由持续挂载的 KeepAlive 容器缓存，跨模块保留文件、岗位、要求、审核建议与生成内容；首页提供“继续当前任务”，主动新建时确认清空。只保存在当前登录会话内，不增加草稿 API 或本地持久化。
- 旧匹配报告按会话、绑定及简历／岗位 ID 和版本隔离；重新分析 queued→failed 保留旧报告并标明版本，成功才替换。旧版本轮询不能覆盖新绑定。
- 评测总览“创建实验”进入实验子路由；手机实验、数据集、版本和案例实际表单均检查单列和内部宽度，按钮文字保持完整。

公共返回调用链为 App 导航／页面状态 → `use-history-layer.js` → History API；弹层通过 `use-dialog-focus.js` 接入。没有增加依赖或改变后端、权限、评分及扩展契约。首轮修复发现横屏发送按钮被挤出视口后，已调整短屏高度，并重新运行相关回归。

修复后全量 Node **297/297**、浏览器 **61/61**（Chromium 59、Firefox 基础 2）和 Vite 构建通过。新增 14 项已进入专项门禁；原 295／47 记录仅代表修复前首轮基线。真实设备和真实服务边界继续适用。

## 2026-11-09 工作区保留补充

用户已明确求职助手跨模块应保留会话、草稿和附件，D01 不再是待决策边界。现在 App 在当前登录会话内保留求职工作区快照，资料 Sheet 的待解析文件及编辑也一并保留；站内返回能力说明不刷新整页。PC／手机附件用真实 File 对象上传到受控解析接口验证字节，退出登录隔离另有浏览器测试。刷新和关页不恢复。该改动只处理 D01；本日 Grill 的 R01–R12 仍见 [审查报告](regression-report-2026-11-09-dual-ui.md)，不等同全平台兼容验收通过。

## 2026-11-09 资料 Sheet 排版与无插件导入方案

根据用户截图调整现有资料 Sheet：PC 保留双列，紧凑布局按内容收缩并限制可视高度；正文 140–200px、主体滚动；两个次操作同排、确认操作独占一行。文件／岗位截图入口前置，长文件名可换行，仍调用原 parse-file API，不新增解析能力或外调。

该排版修正相关浏览器 26 项、最终定向 5 项、Node 297 项及构建通过；真机软键盘与系统分享未作为通过结果。随后已完成下述公开 URL 导入第一阶段，Android 安装后 PWA 分享仍是后续增强。证据、接口复用、许可证比较和推荐顺序见 [资料导入方案](designs/2026-11-09-mobile-material-import-proposal.md)。
