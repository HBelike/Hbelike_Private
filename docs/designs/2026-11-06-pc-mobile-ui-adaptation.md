# PC 与移动端 UI 适配检测及设计方案

日期：2026-11-06。范围为整个 `web-ui` 平台，包含求职助手、职位库、简历助手、面经库、技能库、公众号工作台及管理页面。本文保留实施前检测与设计依据；用户已确认实施，当前变更和验证结果见 [实施记录](2026-11-06-pc-mobile-ui-implementation.md) 与 [双端适配文档](../mobile_ui_adaptation.md)。

建议保留 Vue、Element Plus、现有 API 和蓝白／浅绿主题，以一套业务状态配合两端布局：PC 保留高效多栏，手机以单列主任务、列表与详情切换、辅助抽屉、表单 Sheet 为主。必须先完成 PC 基线验收，再实施手机适配；不安排平板专项。

## 1. 检测范围与当前结论

| 检查 | 本次结果 | 结果适用范围 |
| --- | --- | --- |
| 前端 Node 测试 | 291/291 通过 | 既有逻辑与静态布局合约；不等于真实业务验收 |
| Vite 构建 | 通过，12.63 秒 | 有大于 500 kB 的 chunk 提示，后续移动网络首屏需测量 |
| 既有响应式 E2E | Chromium 5、Firefox 2，共 7/7 通过 | 使用独立预览入口，主要覆盖紧凑 PC；最窄单项为 740px |
| 本次手机布局采样 | 34 个页面／尺寸样本 | 16 个组件预览、16 个真实 App 路由布局、2 个匹配弹窗样本 |
| 应用全局导航 | 390px 下打开、Esc 关闭、焦点返回通过 | 真实 App 壳层、模拟身份与 API 数据 |
| 跨尺寸草稿 | 390 → 1440 → 390 后内容一致 | 求职助手当前选中会话，模拟 API |
| 中文输入法 | 组合输入 Enter 触发 1 次发送请求 | 已复现；请求由测试拦截，不调用真实模型 |

本次使用本地 Chromium 和既有 fixture 隔离后端。App 路由检查采用模拟管理员身份与空数据，证明该状态下的布局表现；不是实际账户、数据库、模型、扩展或公众号发布链路的验收。样本中的“模型暂不可用”来自 fixture 与当前默认模型不匹配，不作为生产故障。

手机组件采样覆盖 `360×800`、`390×844`、`430×932`、`844×390`；真实 App 路由采样覆盖 `390×844`。匹配弹窗另与 `1440×900` 比较。未进行真实 Safari、Android Chrome、微信内置浏览器、软键盘与后台切换验收。

## 2. 实施前发现的问题

优先级含义：P0 阻断核心操作或造成误操作，P1 明显损害阅读与操作，P2 视觉一致性或后续测量事项。

| 优先级 | 发现与证据 | 改造要求 |
| --- | --- | --- |
| P0 | `CareerAssistantPage.vue:2599` 将 Enter 直接绑定发送，未检查 `isComposing`；合成组合输入事件产生了 1 次 `/turns` 请求 | 发送前识别输入法组合状态；手机 Enter 默认换行，显式发送按钮提交；PC Enter 发送、Shift+Enter 换行 |

## 3. 方案比较与技术取舍

| 方案 | 收益 | 成本与限制 | 决策 |
| --- | --- | --- | --- |
| 在现有组件上做响应式与交互收纳 | 复用业务状态、主题、测试和接口；PC 与手机状态保持一致 | 需要清理旧 media query 与 container query 的覆盖关系，逐模块验收 | 推荐 |
| 增加独立手机页面与移动组件库 | 可按手机习惯单独设计 | 聊天、岗位与表单逻辑容易复制；两套页面需要长期同步维护 | 当前不采用 |
| 整体迁移开源管理台模板 | 可获得导航和表单基础布局 | 路由、主题和复杂业务组件迁移成本高，不能解决扩展与采集能力限制 | 仅参考布局思路 |

已核对两个同类开源项目与官方规范：

- [vue-element-plus-admin](https://github.com/kailong321200875/vue-element-plus-admin)：MIT，与当前技术栈接近；查询到的 master 提交记录最近显示 2026-09-01。可参考页面布局边界，整体迁移会引入额外架构与依赖。
- [Admin One](https://github.com/justboil/admin-one-vue-tailwind)：MIT，Vue 3 + Tailwind；查询到的 master 提交记录最近显示 2025-11-27。适合参考轻量导航与卡片排布，照搬将增加 Tailwind 和主题适配工作。
- [Element Plus 设计规范](https://element-plus.org/en-US/guide/design.html) 强调一致性、可理解的反馈和操作可控；保留当前组件基础，统一确认、等待和失败状态。

本方案不引入候选项目依赖，也未进行其依赖安全审计；若后续复制源码，须锁定版本、保留 MIT 许可并单独核对依赖风险。当前复用范围为设计思路。

## 4. 两端共用的视觉与布局规范

### 视觉

沿用现有蓝白主题为默认，浅绿为可切换主题，PC 与手机共用 `theme.css` 变量。

| 角色 | 蓝白主题值 | 用途 |
| --- | --- | --- |
| 页面背景 | `#F5F8FD` | 降低大面积纯白的眩光 |
| 内容面 | `#FFFFFF` | 正文、输入区、Sheet |
| 主色 | `#0064DD` | 当前选中、主按钮、定位证据 |
| 正文 | `#17223B` | 标题与主体内容 |
| 次级文字 | `#526078` | 元数据与状态说明 |
| 分隔线 | `#D7E4F6` | 分组边界 |

标题沿用 `Segoe UI Variable Display / PingFang SC / Microsoft YaHei`，正文沿用当前系统字体栈，代码用 Consolas。页面标题 20–22px，分区 17–18px，正文与输入 16px，元数据 13–14px；中文正文行高 1.6–1.8。不要用 8–11px 承担必要说明。

手机页面左右留白 16px，列表卡片内部 16px，分区间距 16–24px，间距以 4px 为步进；卡片圆角 12px、Sheet 顶角 20px。主按钮高 48px，辅助按钮点击区至少 44px。红色、黄色、绿色状态同时配文字。

### 断点与滚动

保留全局 `≥1280px` 完整侧栏、`1024–1279px` 紧凑侧栏、`<1024px` 导航抽屉。手机专项规则以 `≤640px` 为起点，并以 360–430px 真正手机宽度检验；641–1023px 延续紧凑布局，不增加平板设计。

业务组件继续用自己的 container query 决定多栏／单栏。宽度决定信息重排，高度单独处理横屏与软键盘，不把“宽度小于某值”当成“设备能力不足”。

普通列表／阅读页只有主内容区纵向滚动；聊天页只有消息区作为主滚动面；Sheet 只有内容体滚动，标题和底部操作留在可见区域。代码、原始数据表可局部横向滚动。不能靠全局 `overflow-x:hidden` 判定没有溢出。

使用 `dvh`、safe-area 和弹性布局处理浏览器工具栏；键盘弹起后的可视高度必须真机测试。如果仍有遮挡，再针对聊天与 Sheet 使用 [VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport) 的高度与 resize 事件补充适配，不注册全局轮询或新增状态系统。横屏低高度时收起装饰、辅助说明与非主操作。

## 5. 手机导航与页面设计

示意稿：[三屏设计 SVG](../prototypes/2026-11-06-mobile-ui-proposal.svg)。图中数据为设计示例，不代表真实模型、评分或业务状态。

### 全局壳层

顶栏只保留菜单、当前页面中文标题、账户入口，高约 56px。继续复用现有全局导航抽屉，普通账户只展示已授权模块；管理功能维持原权限。首轮不增加常驻底部导航，避免挤占聊天和表单高度，也避免出现两套不同的主导航。

抽屉占屏宽不超过 86%，点击导航后关闭；遮罩关闭、Esc、焦点返回沿用并补齐测试。手机系统／浏览器返回优先退出当前详情或弹层状态，再返回上一个路由；不得把返回操作变成退出登录。

### 求职助手

主任务为持续对话。手机顶栏下展示会话标题，历史和职位信息为两个短入口；简历、模型和工具操作收进输入区的“资料与工具”，不在输入框上方堆两排控件。

消息正文 16px，长 Markdown 与代码允许正确换行／局部滚动。底部输入框自适应 1–4 行，发送按钮始终可见。等待状态区分排队、生成、失败；保留既有队列与恢复能力。用户向上阅读时不强制滚到底部，新内容用“查看新消息”入口提示。

历史使用抽屉，选择会话成功即关闭；职位信息使用全屏 Sheet，展示 JD、简历摘要与匹配结论，编辑／更换资料仍进入当前已有对话框。跨断点只改变排布，不销毁当前会话和未提交草稿。中文组合输入不发送；手机 Enter 换行，触摸“发送”才提交。

### 职位库与聊天中的岗位检索

首屏是搜索结果：关键词输入一行，城市与筛选共一行；高级条件放筛选 Sheet。岗位卡保留岗位名、薪资、公司、城市／经验／学历、选中状态，不堆全部福利与标签。

选择卡片进入单页详情，顶栏提供“返回岗位列表”；返回恢复关键词、城市、页码、勾选集合和列表滚动。单选确认与批量动作使用底部操作条，详情阅读区预留同等底部空间。

当前实时检索与打招呼依赖同设备的浏览器扩展。手机缺少该能力时，立即说明“当前浏览器无法连接招聘助手，请在电脑端执行实时检索／发送”，提供返回和可用的已有资料入口；已有服务器数据可继续阅读。不能把“安装 Chrome 扩展”当作手机可完成的流程，也不设计未经实现的远程控制电脑功能。

### 岗位匹配分析

手机用全屏报告替代居中窄弹窗。顶部是返回、岗位名、重新分析；摘要为三条横向信息行：“硬性条件”“核心要求”“加分项”，保留区间分数和待核实状态，避免将估计值写成确定概率。

保留“要求对照、JD 原文、简历原文、计算规则”的同一报告内标签。每条要求用卡片呈现原文、匹配状态、简历证据摘要；点击“查看依据”在当前条目下展开证据、定位和待确认事实。手机不把证据栏挤在右侧，也不叠加第二个 Sheet。

重新分析复用原任务队列与轮询；等待期间防止重复提交，失败保留上一次结果并明确其版本；关闭／返回不改变已有报告数据。PC 保留摘要三列、要求与证据双栏。

### 简历助手

历史页保留“新建优化任务”和岗位关键词，起止日期收进筛选 Sheet。结果列表显示岗位、更新时间、状态和“查看”，长标题可换行。

新建任务沿用上传与解析流程，手机按资料、目标岗位、优化工作区逐步完成；工作区用“原简历／修改建议／优化后”标签单页切换，保存保留为明确主操作，离开未提交编辑时给出现有草稿状态或离开提示。解析失败保留已输入 JD，不能因返回标签丢失编辑。

### 面经库

入口聚焦搜索和公司／岗位列表；上传、URL 导入、公开收集放在“导入面经”入口下。树导航用于查找，不与完整阅读正文长期上下堆叠。

阅读详情独占主区域，返回保留公司／岗位展开状态和位置；编辑进入独立编辑状态。导入表单为 Sheet，主体滚动、进度和提交状态可见。小红书等依赖扩展的采集按能力限制提示，普通文件上传与已存内容阅读继续可用。

### 技能库

手机列表突出名称、用途、来源与收藏；详情聚焦内容阅读。编辑使用现有编辑入口的独立状态，正文／预览标签切换，不把目录、编辑框和全文预览同时竖向堆叠；保存操作固定在可视底部并预留空间。需同时验证个人与公共技能权限及保存失败保留内容。

### 公众号工作台

继续保留 `/review` 总览与文章、任务流程、媒体素材、执行历史、生成方案子路由。总览展示本次内容状态与下一步，不在手机总览塞入各子模块的完整正文。

文章页以阅读和审核为主；任务流程用可展开步骤列表，日志独立弹层；媒体素材单列预览，历史按时间卡片显示。生成、重新生成、审核、创建草稿必须沿用原请求和确认步骤，手机仅调整布局与反馈。

### 评测中心与管理页

评测总览使用竖向证据链与单列摘要；数据集、实验与指标管理按单页单任务拆成子路由，列表与详情分开。轻量行数据使用卡片，必须逐列比对的数据使用有提示的局部横向滚动表格。

管理台模块配置将中文名称、状态、开关组成一行卡片；长表单单列。LangSmith 页面优先保留服务状态与打开入口；不在手机窄屏嵌入桌面宽度控制台。

### 面试大师和线上笔试

`browser-live-interview/capture.js` 当前明确拒绝移动浏览器，线上笔试依赖桌面扩展和新窗口。手机提供可阅读的说明、返回求职助手和已有归档阅读入口（仅在已有服务支持时展示），保留清晰的“请在电脑端开启”。

页面能适配手机不代表屏幕共享、系统音频或扩展执行已具备手机能力。禁止根据 CSS 宽度决定业务可用性，也不在本轮新增 App 执行器。

## 6. 实施文件与调用链

调用链保持：`App.vue 路由与权限 → 页面组件 → 既有状态／请求模块 → 原 API 或扩展 bridge`。布局变化不新建第二套请求、业务模型或任务恢复机制。

| 阶段 | 主要文件 | 交付与依赖 |
| --- | --- | --- |
| PC 基线与操作可靠性 | `CareerAssistantPage.vue`、`CareerMatchDialog.vue`、现有 E2E | 先修 IME、确认匹配流程和任务行为，PC 核心回归通过 |
