# BOSS 双向沟通设计

日期：2026-11-05，实施状态更新于 2026-11-09。原九项功能边界及 2026-11-09 两轮复审的六项补充决策已经用户确认，产品决策已收敛；本文保留完整双向沟通设计。本地入站接收、历史持久化与 PC 收件页已实现并通过模拟和本地数据库测试，详见 [BOSS 收件模块](../modules/boss-inbox.md)。源分页、统一账号暂停、单活动执行端及独立发送操作已在本地实现并通过模拟与数据库回归。扩展候选版为 0.6.0；真实账号接口、分页、收件与单条发送闭环尚未验收，未部署生产。

## 实现方向与依据

复用现有 WebUI、Chrome MV3 扩展、本地登录态与 PostgreSQL。新增独立“招聘沟通”子页面，负责列表、正文、草稿和结果展示；通过插件读取 BOSS 求职者会话，并在官方聊天页提交用户确认的文本。

已有公开实现支持求职者会话和历史读取，现有项目具备网页文本提交基础，但完整闭环仍需在本项目账号验证。现有首招流程会执行 friend/add，并跳过已沟通对象，不能直接充当继续回复接口。详细证据及 1,000 次离线故障注入见 [压力审查](2026-11-05-cross-platform-chat-grill.md)。

猎聘、前程无忧的获取职位与发送消息目标继续保留在 [跨平台接入调研](2026-11-05-multi-platform-greeting-research.md)。本设计的 BOSS 技术可行性不能外推为另外两个平台已经打通；外部聊天记录保留 platform 字段，供后续经过验证的适配器使用。

## 页面与调用链

PC 页面建议使用 /career/messages，标题“招聘沟通”。左侧为平台账号、会话列表与摘要；中间为当前会话、文本消息与输入框；岗位关联和连接状态作为当前会话辅助信息。首招仍通过现有入口完成，完整聊天不叠加在首招弹窗中。

~~~mermaid
flowchart LR
  UI[招聘沟通页面] --> HISTORY[平台历史 API]
  HISTORY --> DB[独立外部聊天三表]
  UI --> OPS[发送操作与状态 API]
  OPS --> OPDB[独立发送操作记录]
  UI --> BRIDGE[现有扩展桥]
  BRIDGE --> READ[会话列表与按需正文]
  BRIDGE --> REPLY[官方聊天页单次回复]
  READ --> SYNC[归一化后同步 API]
  SYNC --> DB
  REPLY --> RESULT[可证实的提交状态]
  RESULT --> UI
  RESULT --> OPS
~~~

打开页面先显示平台保存的有效历史和最后同步时间，再检查当前浏览器的插件与 BOSS 账号。列表同步不自动打开全部会话；点开会话后先显示平台已有消息，再按需补充源平台可取得的最近记录。新设备可以查看服务器已保存历史，但该设备发送前仍需具备可用的本地插件和 BOSS 登录态。

首期仅在沟通页面可见且连接就绪时尝试同步。页面切到后台即停止发起后续轮询；回到前台后立即尝试补齐，账号处于暂停状态时仍须手动继续。浏览器打开、沟通标签页存在，不等于正在同步。页面休眠、浏览器关闭、断网和源平台登录失效时明确显示同步状态，不承诺全天候收件或固定毫秒级实时性。已经开始的读取与后台排队操作必须区分，停止轮询不等于取消了在途请求。

### 源历史补齐与同步完整性

已选会话先显示平台已保存的正文，再按需向源平台继续读取最近 30 天仍可取得的记录。网页 bridge、Content Script、Service Worker、MAIN 读取器须完整传递经过真实账号验证的分页或游标参数，并返回源分页状态；数据库历史翻页不能替代源平台补取。

重新进入页面、从后台恢复或断网恢复时，对当前会话补取新消息，直到与上次已确认连续同步区间衔接，或取得经过验证的源结束信号、到达 30 天边界。单条重复消息、某页条数不足或缺失 has_more，不能未经验证便视为历史完整。不能补齐的区间显示“同步不完整”及原因，不以“暂无消息”掩盖。未选会话仍只更新摘要，不因此批量读取全部正文。尚未同步且源平台不再提供的内容不能凭空补全。

### 单活动执行端与账号暂停

跨页面、浏览器和设备的活动执行端归属需要统一判定；仅有单个 Service Worker 的串行队列不足以满足这一目标。非活动端可以查询平台历史，不主动读取 BOSS 或提交消息。活动资格失效后，旧端尚未开始的操作不得继续执行；已经触发提交的操作仍按证据核对结果，不转交新端重发。

接管采用手动方式：新页面默认查询历史，用户点击“在此接管”后才申请活动资格。旧端失去资格后不得启动新操作；新端不继承旧端待发队列，也不重发待核对操作。已进入提交阶段的旧操作必须先收尾或明确停止；不能仅因为接管按钮已点击，就与仍可能提交的旧操作并行执行。

活动资格由服务端按当前登录用户与外部账号统一管理，至少记录执行端标识、资格版本和有效期；扩展真正执行前及提交前核对当前资格。页面选中状态、扩展内存队列和设备名称均不能作为跨端执行权依据。服务端不可达、页面不再可见或无法确认当前资格时，不启动新的源平台动作。只复用现有数据库事务完成必要协调，不引入独立消息系统或整套 Agent Worker。

验证码、登录失效和限流等账号级暂停要约束该账号的后续自动同步与发送，不能因新开页面、重新加载或另一个队列请求而绕过。暂停状态需在执行层共享并跨页面重载保留；切换活动端不自动解除暂停。人工处理后，用户在活动端手动检测并继续。当前实现使用账号执行字段及 chrome.storage.local 共同保存暂停；执行资格 90 秒，由可见页面每轮检查续期，手动接管递增版本。失去资格的端只查看平台历史。

## 桥接动作

| 动作 | 责任 |
| --- | --- |
| get_chat_state | 返回当前平台账号身份、连接状态、暂停原因和实际可用能力 |
| list_conversations | 读取求职者会话、对方身份、最新消息、时间和可取得的未读数 |
| get_messages | 按已验证的会话身份读取正文和平台消息 ID，支持继续加载可取得的历史 |
| reply_message | 对已存在会话提交一条用户确认的文本，不执行首次建联 |
| cancel_chat_operation | 使尚未提交的操作失效；取消结果须区分确未提交与结果待核对，不能撤回已经点击提交的消息 |

动作命名为拟定接口。实现时必须同时更新网页 bridge、Content Script 动作白名单、Service Worker 分发器、能力握手和扩展 ZIP 清单。新增文件只在本地加载成功而未进入下载 ZIP，不算交付完成。

## 会话身份与发送

外部账号按当前平台用户、招聘平台和稳定账号 UID 归属。会话优先采用平台会话 ID；没有独立会话 ID 时使用经验证的账号及对方 UID 组合。岗位是关联信息，同一 HR 可涉及多个岗位，不能按岗位 ID、姓名、公司名或列表序号决定发送对象。

用户点击发送时冻结目标账号、会话、最终正文和本次 client_operation_id。插件在写入前及提交前核对当前账号、对方身份与限制状态；检测到未发送草稿、切号或切会话时要求用户处理，不覆盖原草稿。securityId 等动态字段每次按当前源数据核对，不当作永久联系人 ID。

一次确认仅产生一次提交尝试。同一 client_operation_id 的重复请求只返回已有状态，不重新执行；用户修改目标或正文、新发一条相同文本时，均须重新确认并使用新操作 ID。网页等待超时不等于后台尚未执行，旧操作在用户点击重试、页面重载或执行端接管时也不得重新提交。

状态明确区分：待提交、已触发提交、平台已接受、明确失败、结果待核对。只有真实业务回执或经验证的源消息证据才能提升状态；单次 click、清空输入框、乐观气泡或传输 ACK 均不足以证明对方收到。已读状态也只在源平台提供对应证据时展示。

验证码、登录失效和限流暂停该外部账号的后续自动同步/发送。缓存历史仍可查看；用户完成平台处理后可手动检测、继续。恢复连接不重放已经提交或结果未知的操作。

### 发送操作与结果核对契约

外部聊天消息表仍要求真实平台消息 ID 和源时间非空；发送状态不混入历史消息。当前已新增执行资格与操作 API，待发操作独立存储为 external_chat_operations，复用当前数据库与用户归属，不能把网页 bridge 的临时 requestId 当作持久化操作 ID，也不编造源消息 ID 或源时间适配现表。

操作记录最少保存 client_operation_id、所属账号和会话、冻结正文、执行端及资格版本、服务端确认时间、expires_at、状态和可核实的源消息 ID。操作 ID 按当前用户与外部账号唯一；确认创建、领取执行及取消使用条件状态更新，避免重复请求各自产生一次尝试。网页须先成功创建服务端操作记录，再向本地扩展分发；服务端失败时不执行发送。服务端提供按操作 ID 查询状态的能力，刷新页面只恢复展示，不重新分发旧操作。

离开沟通页、切到后台、等待超时、活动资格变化或操作过期时，使尚未触发提交的操作失效；回到前台、恢复网络或重新加载扩展后不恢复旧发送。初始执行有效期采用服务端确认后 30 秒，网页等待期限不得据此延长操作有效期；该参数只限制何时还能开始提交，不把超时等同于明确失败。执行前及点击提交前重新检查账号、会话、活动资格、页面状态、取消状态和有效期。若已经填写但尚未提交，停止后保留草稿并提示处理，不覆盖或删除用户后续修改。

取消必须能先更新操作有效状态，不能排在待发任务之后。现有所有非 ping 请求经过同一串行队列，若取消也排在待发之后，会出现“耗时读取 → 发送 → 取消”的顺序，无法阻止发送。取消指令已发出、网页超时或移除回包监听，均不等于操作已经取消。只有执行端能够证明确未触发提交时，才展示“已取消”或“已过期”；取消与提交交错、执行端中断等无法确定的情况先进入“待核对”。这些规则用于阻止旧操作重放，不承诺对源平台实现严格 exactly-once。

没有可靠回执或可核对关联时，旧操作保留“待核对”并提供到 BOSS 查看入口，不提供重新执行旧操作的按钮。只允许依据经过验证的业务回执或源消息关联更新为“平台已接受”；正文相同、时间接近、输入框清空及用户口头确认均不能冒充平台技术回执。用户主动查看源平台后，可另行确认新消息，即使正文相同也作为新操作；该交互明确提示旧结果仍未证实，存在重复发送的可能。源历史按真实消息 ID 去重，不能为了消除待核对占位而误删真实消息。待核对操作按保留期限到期删除，不因长期未知转成失败或重新发送。

账号限流或验证继续按既定规则暂停；单条结果未知仅影响该操作，不据此自动判定整个账号被限流。进入提交阶段后发生刷新、扩展重启或失联时，重新加载只查询状态；不能因为内存中已无记录，就推断旧操作没有执行。

## 独立存储与权限

| 数据 | 最小内容 |
| --- | --- |
| external_chat_accounts | 组织、当前用户、招聘平台、稳定账号 UID、显示名称及最近观察时间；后续增加活动端资格与账号暂停字段 |
| external_chat_conversations | 外部账号、平台会话 ID、对方 UID 与显示信息、必要岗位关联、同步时间及有效摘要 |
| external_chat_messages | 会话、真实平台消息 ID、发送方、方向、类型、文本/类型占位、平台原始时间和接收时间 |
| external_chat_operations | 当前用户、账号、会话、client_operation_id、冻结正文、执行端及资格版本、确认时间、有效期、提交状态及可核实的源消息关联 |

复用 CareerDatabase 与 actor_id 查询模式，所有导入、查询和状态更新从服务端登录身份确定归属。换设备查看同一用户的记录，不按浏览器设备 ID 划分历史；不因管理员能管理简历就自动开放他人的 HR 私聊。

平台消息 ID 以字符串保存，并按其实际作用域建立去重键。保留原始时间，稳定排序；重复同步合并源消息，不能按正文或接近的时间猜测是同一条。未读字段缺失显示未知，不默认为零。

HR 聊天使用独立仓储和 API，不写入现有 LLM 会话表。保存历史不等同于把全部聊天发送给模型；AI 起草必须由用户主动触发，草稿与 HR 原文、用户已发消息区分来源。

未确认草稿保留在当前页面；用户确认发送后才创建服务端待发记录，并冻结该次操作的目标与正文。

非文本消息仅保存识别类型所需的信息和可用的源会话入口，不在本期保存图片、音频或附件文件，不声称已经完成媒体预览、下载或发送。

## 最近 30 天保留规则

“最近 30 天”按平台消息原始时间滚动计算，服务端以 UTC 计算 cutoff = now - 30×24 小时，展示采用用户时区。导入和查询包含原始时间等于 cutoff 的消息，物理清理删除早于 cutoff 的消息。不能从导入时间重新起算，以免把很早的聊天导入后又保存 30 天。

- **导入**：只接收窗口内的源消息；过期源消息不重新入库。无法可靠解析时间时，不以当前时间冒充源时间，应标记同步不完整并核对来源。
- **查询**：正文、搜索、数量、最新消息和会话摘要统一应用 30 天窗口；查询不能因后台清理尚未完成而展示过期内容。前端恢复、刷新与本地缓存更新时也丢弃窗口外的已加载正文。
- **清理**：API 生命周期在聊天数据库启用时启动补清一次，随后每 60 秒调用同一到期清理函数，服务关闭时取消该周期任务。使用现有数据库事务删除过期消息并修正摘要，不初始化 LLM 服务；未启用数据库的预览模式不启动清理。不把当前只支持周任务的公众号 Scheduler 当作聊天 TTL 调度器。
- **摘要与占位**：过期正文、非文本占位及其消息预览同步清理；联系人/账号标识可独立存在，但不得借摘要继续保存已过期消息内容。
- **发送操作**：还没有平台原始时间时，以本次用户确认操作的服务端创建时间管理待发、失败及待核对记录的 30 天保留期；取得可核实的平台时间后按源时间校准，不能因此延长原定保留截止时间。状态更新不重置到期时点。正文保留期限与 30 秒执行有效期分别管理；到期清理不意味着源消息失败、未送达或可以重发。真实源消息仍按其自身平台时间执行 30 天规则。
- **其他副本**：业务日志不记录完整消息正文，AI 草稿和其他实际保存的消息内容遵守对应的保留范围；不额外保存原始接口响应作为长期聊天副本。
