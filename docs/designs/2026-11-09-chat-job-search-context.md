# 对话求职结果与模型上下文接通

## 目标与根因

用户已经通过对话卡片获取网易云岗位，再问哪些岗位适合自己时，助手应读取这些岗位与已确认简历，给出有依据的具体岗位推荐。

旧实现只把求职组件放进消息：搜索结果在浏览器获取、卡片通过 `ui_payload` 保存，但新旧 Prompt 构造只使用历史 `content_text`，模型看不到卡片里的岗位。历史摘要也不含学历、经验、技能与 JD。此外，“推荐岗位”既可能是新搜索，也可能是分析已有结果，原路由会用关键词覆盖语义确认的分析意图。

## 数据与调用链

`JobSearchWorkspace` 搜索成功 → `summarizeSearchJobs` → 卡片 PATCH；现有详情加载与预取成功 → `mergeJobDetail` → 保存匹配证据 → 追问提交前等待已发起的保存 → `PromptContextService` → `job_search_context_messages` → 模型结合岗位与简历作答。

- 复用 `ui_payload`、PATCH、详情加载器与上下文预算，不增加迁移、外部依赖或新的采集动作。
- 继续最多十条摘要并保留完整结果总数；新增可选经验、学历、技能和 `description_excerpt`，上限分别为 120、120、600、2000 个 Unicode 代码点。`degree` 映射为学历；原始完整 JD 与运行时对象不修改。
- 新搜索开始清空当前卡片旧摘要。未返回和零结果分别表达为 `not_returned`、`returned/0`，不能重用旧结果冒充新结果。
- 详情合并仅在摘要变化时发布保存；追问等待已发起的 PATCH，保存失败按现有失败消息机制反馈，不能默默将缺失上下文的消息入队。
- 新增独立 `job_search` 必需 Prompt 组件，加入实际 Token 核算，与文字历史压缩分离。兼容旧 Runner，同步、流式共享数据构造。取当前输入之前最近一张求职卡片，排除后排队消息；从最近 200 条消息中读取，窗口内找不到当前输入时保守不注入。
- 意图模型只接收搜索条件与岗位名称/公司，不重复接收 JD 和长标识。已有结果下泛化“推荐几个岗位”走分析；语义确认的结果推荐不被“推荐”关键词变回新搜索，明确新搜索仍开卡。

## 回答与交互边界

模型区分检索候选、用户目标岗位与候选人经历。推荐说明具体岗位、公司、简历证据、要求与差距。无简历不能断言适合，无 JD 仅作初筛；不能编造 JD、匹配分、录用概率或声称分析了未提供的岗位。公司名称按数据核对，不混淆网易与网易云，不猜测隶属关系。结果是搜索快照，不保证当前仍在招。

数据不包含桥接用标识，材料按无指令权限封装。只有用户点击“设为目标岗位”才更新绑定。

本次接通搜索后的多轮分析，不新增搜索完成自动回复、模型直接操作浏览器、跨会话记忆、多批岗位联合排名或超过 200 条消息窗口的召回。旧摘要可用于初筛，旧记录未保存的 JD 需重新搜索并获取详情才能补齐。

## 本地验证

- Python 定向回归 112 项通过，包含真实 `PromptContextService` 和同步/流式 Runner 将网易云岗位、JD 摘录、简历送入模型参数；覆盖历史压缩、旧摘要、空结果、未返回、排队隔离、材料封装及推荐意图。
- 前端 Node 全量 317 项通过；Chromium 对话回归 12 项通过，包含刻意阻塞 JD 保存、确认追问未提交、释放后检查服务端已获得 JD，以及刷新保留数据、不重搜、不改变目标岗位绑定。
- Vite 构建成功，保留既有 chunk 大小提示。
- 已确认数据库仅连接本机 127.0.0.1:54329，当前 Worker 无活动租约任务后重启本地 Worker；前端 5173、后端 18080 健康请求均返回 200。遗留无租约运行记录未改动。
- 模型使用测试客户端，浏览器使用合成岗位与 API fixture。未调用真实模型、定位或 BOSS 发送，未部署生产。
