# 面试大师长连接修复与本地验收

11 月 19 日晚和 20 日下午分两轮验收，每轮同时运行两场本地面试，四场都实际持续了 **61 分 6 秒**。每场在同一条 WebSocket 连接上跨过一小时后仍能收音、转写、获取模型回答，最后一句进入会话历史。此前 11 月 18 日的三次生产中断，日志都记录了旧版两秒音频队列满，由 API 关闭当前连接。同一时间窗口内没有观察到容器重启或 OOM。触发积压的具体原因仍未确定。[故障时间线和历史发布版本](2026-11-19-live-interview-hour-and-incidents.md)

## 四个真实面试场景

| 场景 | 修改和验收方式 |
| --- | --- |
| 一帧后返回多句，字幕和回答停在第一句 | 转写与音频帧独立编号。按供应商的句号或 item ID 去重，没有编号时按定稿推进。多服务用例让同一帧一次返回两句背景，逐条核对字幕和数据库历史。适配器另测从 0 开始的句号、重复定稿以及 OpenAI 的乱序定稿。 |
| 面试官讲到一半就触发回答 | 陈述先出字幕，保留为本轮背景。测试先说“我们有两个消息队列”“同一条消息可能重复到达”，再问“如何保证消息处理幂等？”，断言只生成一题且题干含两项约束。 |
| 上游短暂停顿、连接断开或按下结束，造成漏音、漏尾句 | 后端每轨六秒缓冲，心跳独立处理。浏览器对已授权音轨继续采集，每轨暂存最近五秒尚未发送的音频。两实例用例让 ASR 主动断开，收到 1013 后在另一实例续同一场；结束用例让 ASR 只在收到收尾请求时返回最后一句，核对字幕事件、结束确认与最终记录。 |
| “它有什么缺点？”漏掉前文 | 已判定的追问使用近期发言、上一题及匹配的已完成 AI 建议，提示词区分发言来源。跨实例用例逐项核对第二次模型请求包含追问、原题和上次方案。两题总计两次模型调用。 |

## 实时长测与故障回归

测试在回环网络上启动 FastAPI 业务端、兼容 DashScope 协议的 ASR WebSocket、兼容聊天模型的 HTTPS SSE 服务，数据库使用单独的 PostgreSQL 16 容器。服务使用单独的 TCP 端口，Uvicorn 实例在同一测试进程内运行。每 100 ms 发送一个 24 kHz PCM16 帧，ASR 按合成音频中的标记返回指定台词，模型分块返回指定回答。客户端从收到就绪开始按单调时钟计时，断言每场落库的定稿数、完成回答数及结束状态。

每轮均调用模型 126 次。两轮 pytest 分别用时 3667.87 秒和 3667.92 秒。最终一轮还逐句比对了输入脚本与收到的字幕文本，并检查了每场的回答版本连续递增。以下为故障、并发及页面回归结果。

- 同一个会话在两个独立 API 实例间竞争时，后到的连接收到 4409。首个实例的上游掉线后，第二实例恢复同一会话，保存五条转写、两份回答。正常结束后，两个实例都对重开请求返回 4410。
- 传输层短时运行 1、8、32 条并发连接，均未意外断开。8 和 32 条并发各持续 3 秒，心跳往返 P95 分别为 3.768 ms 和 4.254 ms。此项使用本地慢写入替身，只测连接转发与资源释放。
- 四场并发 12 秒，各送达 121 帧、5 条定稿、2 份完整回答。另两场并发 68 秒，各送达 681 帧、6 条定稿、3 份完整回答，覆盖首分钟新增问题。
- 第二轮跨小时测试运行期间，独立启动一组 10 场并发的多服务测试，共享同一台 PostgreSQL。10 场各持续 366.02～366.04 秒，各送达 3,661 帧、收到 19 次心跳回执、11 条定稿和 8 份完整回答。模型共被调用 80 次，最终历史逐场核对通过。
- 口语用例覆盖“为什么”“缺点呢”“能举个例子吗”的自动和手动作答，以及恢复后承接最新排队题的追问。明确给出新主题的“举个数据库索引失效的例子”按独立题作答。
- Chromium 页面连续接收 102 条定稿，上翻时计数和回到最新字幕均通过。若 WebSocket 提前正常关闭而缺少应用层结束确认，归档弹窗会提示最后一句可能不完整。
- 另一次从 Chromium 真实页面起步，合成共享音轨经 AudioWorklet、业务 WebSocket、本地 ASR 与 HTTPS SSE 服务写入 PostgreSQL。共发送 31 帧有声 PCM（73,728 个样本），页面收到 5 条定稿、4 条回答增量、2 份完整回答和结束确认。最终历史包含尾句，归档预览返回 2 题。
- Python 全量回归 978 项通过、29 项跳过。连接隔离 PostgreSQL 后，面试模块 129 项通过、1 项按需慢测跳过、2 项多服务用例单独运行；额外慢测另行通过。前端单测 378 项通过，Vite 生产构建通过。

## 复验

从仓库根目录运行，在环境变量 `LIVE_INTERVIEW_SOAK_DATABASE_URL` 中指定已迁移的本机专用 PostgreSQL 库。测试只清理自己创建的会话。复验跨实例故障时把 `-k steady` 换为 `-k reconnect`。

```powershell
$env:LIVE_INTERVIEW_SOAK_SECONDS = '3666'
$env:LIVE_INTERVIEW_SOAK_CLIENTS = '2'
.\.venv\Scripts\python.exe -m pytest tests/test_live_interview_multiservice.py -k steady -q -s
```

## 适用范围

默认前端在第 115 分钟提示，第 120 分钟结束。真实云端 ASR、模型延迟、会议软件共享音轨与公网代理仍会影响实际面试。浏览器每轨五秒暂存满后会舍弃最早的未发送音频并提示；已经交给旧 WebSocket 的帧没有逐帧识别确认，断线瞬间可能有缺字。备用 OpenAI ASR 使用单会话断开后接续的路径，两场一小时测试采用 DashScope 协议服务。OpenAI 按 item 返回转写结果，完成事件可能乱序。[OpenAI 转写协议](https://developers.openai.com/api/docs/guides/realtime-transcription)

两实例恢复要求原连接完成清理。API 进程被强制终止时，数据库可能残留 `active`，后续实例会拒绝抢占。这次也没有测真实云端中文识别准确率、首字延迟或 10 场各 90 分钟的并发容量。本次修改和验收都在本地完成。
