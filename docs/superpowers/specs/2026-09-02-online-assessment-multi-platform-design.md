# 线上笔试助手多平台识别与可靠作答设计

日期：2026-09-02

## 目标

线上笔试助手不能依赖单一 LeetCode DOM。用户在任意 HTTP(S) 笔试页主动点击扩展后，系统应优先读取当前视口内的可见题面和编辑器，再通过已知平台 Adapter、通用语义提取、必要时的视觉复核与人工确认，形成统一题目契约。算法题进入代码生成、测试和修复；SQL、选择题和简答题进入不带执行承诺的参考答案流程。

本次同时修复当前真实故障：模型返回 JSON 对象但不符合 `AssessmentSolution` 时，系统应在同一生成任务内纠正一次格式，而不是直接显示“答案结构不符合契约”。

## 非目标

- 不自动滚动、点击题目站点、填写编辑器或提交答案。
- 不读取隐藏 DOM、隐藏测试、Cookie、密码或登录 Token。
- 不为 SQL 宣称本地执行通过，不为选择题或简答题伪造测试结果。
- 不远程下发可执行 Adapter JavaScript，不增加 `<all_urls>` 权限。
- 不在当前阶段内置 OCR 模型；视觉失败时安全降级为人工确认。

## 方案选择

采用分层混合识别，而非“为每个平台堆选择器”或“所有截图直接交给模型”。开源证据包括：

- `jmerle/competitive-companion`（MIT）：统一 Parser Registry、平台 Fixture 与选择器回退。
- `serenadeai/chrome`（MIT）：Monaco、CodeMirror、Ace 与原生输入框的只读编辑器桥接。
- `Fanfulla/OCR-buddy`（MIT）：用户触发的当前视口截图与临时识别；不复用自动滚页能力。

第一阶段深度 Adapter 为 LeetCode、HackerRank、牛客。CodeSignal、Codility、赛码在取得真实或脱敏 Fixture 并通过验收矩阵后再标记为深度适配；此前仍走通用识别。

## 总体调用链

```text
用户点击扩展
  → Adapter Registry 匹配已知平台
  → 通用语义 DOM 与只读编辑器桥接补全
  → Capture Contract V2
  → 确定性完整度检查
  → 低置信度/Canvas/iframe/语言冲突时调用视觉复核
  → 仍不完整则人工确认
  → 按题型路由
      ├─ 算法题：生成 → 格式纠正至多一次 → 测试 → 代码修复至多两轮
      ├─ SQL：生成 SQL 与思路，标记未执行
      ├─ 选择题：答案与依据
      └─ 简答题：结构化参考答案
  → 用户确认后可归档到面经库
```

## 扩展采集架构

### Adapter Registry

Adapter 是随扩展打包的纯数据定义，只包含：

- 安全平台 slug、根域名与子域名匹配；
- 页面类型；
- 标题、题干、语言控件、编辑器、样例块等选择器集合；
- 语言别名和样例分组规则；
- Adapter 版本。

Adapter 不包含点击、滚动、写页面、访问 Cookie 或任意脚本执行。注册表通过 `chrome.scripting.executeScript` 的 `args` 传给自包含采集函数，避免 Chrome 只序列化函数导致模块闭包不可见。

### 通用采集

未知平台按字段独立寻找证据，不再把最长 `main.innerText` 当题面：

- 标题：文档标题、题目标题语义节点；
- 题干：当前视口内的可见叶节点，拒绝导航、表单和大型非视口容器；
- 编辑器：Monaco、CodeMirror、Ace、textarea，只读取可见候选；
- 语言：控件文字、编辑器 mode/languageId、starter code 三层推断；
- 样例：输入、输出和解释分别提取后成组；
- 函数入口：支持 Python `def`、JS 声明与 `name = function(...)`、Java/C++ 方法。

只读编辑器桥接使用随机请求 ID、固定 action 白名单、来源校验和只读返回值，不暴露 setter、run 或 submit。

### 标签页绑定

一次题面领取绑定 `sourceTabId`、`sourceWindowId` 和 `sourceOrigin`。同源路径变化允许重新识别；跨源导航后要求用户重新点击扩展。

## Capture Contract V2

保留现有字段，并以可选默认值增量加入：

- `problem_type_hint`：`algorithm`、`sql`、`multiple_choice`、`short_answer`、`unknown`；
- `candidate_languages`：语言候选及来源；
- `field_evidence`：各字段的 DOM、编辑器、Adapter 或视觉证据类型，不保存原始 HTML；
- `capture_warnings`：截断、冲突、跨 iframe、Canvas、语言未知等代码；
- `adapter_version`；
- `primary_problem_candidate`。

旧扩展缺少新增字段时仍可提交。平台只作为元数据使用安全 slug 清洗，不再被后端固定白名单压回 `generic`。

## 完整度、置信度与视觉复核

确定性完整度是权威闸门，模型不能覆盖硬缺失项。算法题自动解答至少需要：完整题干、明确语言、明确接口类型，以及函数题可调用入口或标准输入输出约定。

出现以下任一条件时才尝试视觉复核：

- 确定性置信度低于 0.65；
- 存在硬缺失项或语言冲突；
- 页面主要内容位于 Canvas 或不可访问 iframe；
- 用户补充的新视口与既有题面冲突。

视觉复核复用项目已验证的 Qwen `qwen3.6-flash` CloudVision 连接，通过笔试专用结构化 Prompt 只补缺失字段。视觉服务不可用、缺 Key、超时或截图非法时，保留 DOM 结果并进入人工确认，不让整次分析失败，也不抬高置信度。页面需提示低置信度时当前视口会发送给配置的视觉 Provider。

## 语言权威与跨语言切换

- 首次识别按语言控件、编辑器 mode 和 starter code 推断，不再未知即默认 Python。
- 用户在助手中明确选择的语言成为最终权威。
- Python 与 JavaScript 可基于函数名和参数名生成目标接口约束，同时清除旧语言 starter code。
- Java/C++ 缺少参数或返回类型时要求用户回平台切换语言后重新识别，不能从无类型 JS 签名猜测。
- 语言切换立即清除旧答案、测试结果和不兼容的 starter code。
- 执行与自动修复前强制校验题目语言和答案语言一致。

## 模型答案契约纠正

每个生成任务最多调用答案模型两次：首次生成和至多一次格式纠正。纠正仍使用同一模型，不自动切换服务商。

可纠正错误包括：非空但无效 JSON、Schema 校验失败、代码为空、额外字段和语言不一致。网络、鉴权、额度、空回答不纠正。允许的确定性兼容仅为：

- `assumptions: null` → `[]`；
- `assumptions: "文本"` → `["文本"]`。

第二次请求在内存中携带最多 32,000 字符的旧答案和安全化字段错误；超过上限则根据原题重新生成完整答案。原始回答不落库、不写日志。服务端只记录模型档案键、纠正次数及如 `code: missing` 的字段错误。

流事件顺序为：

- 正常：`generating → solution → done`；
- 纠正：`generating → correcting → solution → done`；
- 纠正失败：`generating → correcting → error`。

保留现有 `solve()` 兼容调用，新增进度迭代接口供 Web 路由实时输出 `correcting`。

## 题型路由

- 算法题：沿用代码生成、公开样例、AI 边界测试和最多两轮代码修复。
- SQL：生成 SQL、方言假设与思路，明确标记未执行。
- 选择题：返回选项、推荐答案和依据，不生成代码。
- 简答题：返回结构化参考答案，不生成代码。
- 未知题型：人工确认后再路由。

页面仍遵守单页单任务：同一题只呈现与当前题型相关的工作区，不纵向堆叠所有题型模块。

## 隐私与留存

- 原始截图、HTML 和模型未校验输出不落库。
- 无正文诊断只记录平台、Adapter 版本、题型、缺失代码和失败阶段。
- 低置信度视觉复核会把当前视口发送给平台配置的外部视觉 Provider，产品需明确提示；供应商侧留存不由本项目保证。
- 用户明确归档后，面经库只保存确认题面、最终答案、思路、复杂度与测试摘要。

## 验收矩阵

平台只有同时满足以下条件才显示“深度适配”：

- 真实或脱敏页面 Fixture；
- 根域名、子域名和伪后缀攻击测试；
- 标题、正文、语言、编辑器、函数入口和样例提取测试；
- 视口外、隐藏节点和巨大滚动容器不采集；
- `executeScript` 序列化隔离测试；
- 至少一次真实浏览器识别；
- 页面改版或低置信度时安全退回通用识别。

答案链路需覆盖：首次格式失败后纠正成功、连续失败、语言不一致、网络错误不纠正、手动重新生成获得新的单次纠正机会、Python/JavaScript 真实生成和公开样例执行。

## 实施阶段

1. 先修复当前答案契约故障、语言默认和 JS 匿名函数入口，恢复 LeetCode 可用性。
2. 建立声明式 Adapter Registry、通用采集与 V2 增量契约。
3. 接入低置信度视觉复核和确定性完整度闸门。
4. 完成 LeetCode、HackerRank、牛客 Fixture 与真实验收。
5. 增加 SQL、选择题、简答题答案路由；CodeSignal、Codility、赛码取得 Fixture 后再升级为深度适配。
