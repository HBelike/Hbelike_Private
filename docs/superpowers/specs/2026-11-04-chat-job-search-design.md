# 对话内找工作设计

## 已确认的交互

- 识别用户当前寻找实际岗位的任务，直接在助手消息中展示现有职位检索能力。就业行情、改简历、面试准备、分析已有岗位不误触发；方向尚未明确时先帮助明确方向。
- 明确要求检索且岗位关键词可靠时，在定位或手动选择补齐城市后自动搜索一次；泛求职意愿展示待填写表单。混合诉求允许求职卡片和文字回答同时出现。
- 岗位条件优先本轮表达，再使用已确认条件。城市优先明确条件；没有明确城市时获取用户位置，未授权或定位失败时询问启用定位并允许手动选城。不得静默使用上海或浏览器旧城市。
- 搜索前补充条件更新当前卡片；搜索完成后的新请求创建新卡片，历史保留结果摘要。历史加载和刷新不重新搜索。
- 查看详情不更改上下文；点击“设为目标岗位”才调用现有岗位档案和会话绑定接口。反馈遵循真实分析状态。不会触发投递或打招呼。
- 自动搜索缺扩展或需登录时在卡片内提示；定位坐标只用于即时城市解析，不持久化。

## 调用链与存储

现有 Turn 入队与材料处理 → 规则和轻量语义意图判断 → 回复分流 → 带 ui_payload 的助手消息 → CareerJobSearchCard → JobSearchWorkspace → 浏览器职位库桥接。城市定位由浏览器 Geolocation 获取本次设备坐标，再由浏览器直连 BigDataCloud 客户端接口解析城市；不提供服务器代理，不持久化坐标，失败允许手动选城。

消息增加可空 JSONB ui_payload；最终回复、后台 Worker 和历史读取使用同一结构。仅记录条件、卡片状态、最多十条结果摘要和已确认岗位摘要。复用前卡条件或已确认岗位固定头部，不重新接入已停用的跨会话记忆，也不从 JD 正文推测城市。编辑已有卡片通过受会话所有权约束的更新接口持久化，回复事件携带 updated_messages 更新当前视图。

现有 Turn 已冻结提交时的岗位上下文，沿用该行为。搜索组件独立页面和旧弹窗继续使用原模式。
